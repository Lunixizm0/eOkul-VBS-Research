# 09 - Reproducing the build from a fresh clone

The repository contains the research artifacts and build scripts. Reproduction
additionally requires the original MEB APK split files, which must be obtained
separately and placed under `apks/original/`.

```bash
git clone <repo> && cd eOkul-VBS-Research
./scripts/setup.sh      # tools, .venv+mitmproxy, keystore, engine, input checks
./scripts/build.sh      # -> apks/VBS-Mod.apk
adb install -r -d apks/VBS-Mod.apk
adb shell pm clear com.meb.vbsmobil   # only when upgrading from a build with encrypted prefs
```

`make setup / build / install / capture / verify / flows` are thin wrappers around the
same scripts.

## What `setup.sh` does (idempotent)

| Step | Detail |
|---|---|
| 1 | checks `java`, `keytool`, `python3`, `unzip`, `zip`, `curl`, `sha256sum`; warns about missing `llvm-strip`, `adb`, build-tools |
| 2 | puts `apktool` at `tools/apktool.jar` (downloads v3.0.3 from GitHub, or reuses `APKTOOL_JAR` / `~/tools/apktool_3.0.3.jar`) |
| 3 | creates `.venv` and installs **mitmproxy** (only needed for capture) |
| 4 | generates `keystore/test.keystore` (alias `test`) and writes the random password to `.env` as `KEY=…` |
| 5 | verifies `apks/original/*.apk` against `input-sha256.txt` |
| 6 | runs `scripts/fetch-engine.sh` |

## Inputs

| Path | Origin | Verified by |
|---|---|---|
| `apks/original/base.apk` | MEB eOkul VBS `3.3.2` (versionCode 69), base split | `input-sha256.txt` |
| `apks/original/split_config.arm64_v8a.apk` | native libs for the same version | `input-sha256.txt` |
| `apks/original/split_config.{ar,tr,xxhdpi}.apk` | language/density splits | `input-sha256.txt` |
| `dump/strings_dump.json` | ghost-class field values dumped from memory (committed) | `aa0ba3f738ac1040c638ca34778c08f2d898f6bc739eb0b3effcc072b8b9aa3b` |
| Flutter engine artifacts | downloaded by `fetch-engine.sh` | pinned sha256 |

The original MEB APKs are **not** committed to the repository (proprietary input). Place
them under `apks/original/` manually before running `setup.sh`; their SHA-256 values are
pinned in `input-sha256.txt` and verified by step 5. To rebuild from a different app
version, replace `apks/original/*` and regenerate `input-sha256.txt`:

```bash
sha256sum apks/original/*.apk > input-sha256.txt
```

Everything else (the 1361 string values, the engine addresses) is version-specific and
would have to be re-derived - see `03-strings.md` and `04-native-engine.md`.

## Engine

`fetch-engine.sh` downloads the official Flutter engine artifacts for revision
`d2913632a4578ee4d0b8b1c4a69888c8a0672c4b` (Flutter 3.35.6)

then extracts `lib/arm64-v8a/libflutter.so`, applies `scripts/engine/cert_bypass.py`
(`ssl_crypto_x509_session_verify_cert_chain` 0x716b60, `X509_verify_cert` 0x6fb758 -
`mov w0,#1 ; ret`) and strips it. Both patch sites are re-read and verified byte-wise, so
a wrong engine revision fails loudly instead of producing a broken APK.

## Build

```bash
./scripts/build.sh           # reuse build/apktool
./scripts/build.sh --fresh   # re-decode apks/original/base.apk first
```

The smali storage fix is a vendored file (`scripts/patch/assets/k2_a.smali`) whose
sha256 is pinned alongside the original `k2/a.smali`, so `--fresh` reproduces it and a
different app version fails loudly instead of silently applying the wrong patch.

`build/apktool`, `build/out`, `build/split`, `build/mitm`, `.venv` and `tools/` are
gitignored. `.env` is regenerated by `setup.sh`; `APKTOOL_JAR`, `BT`, `KEY_ALIAS`,
`OUT`, `API_URL` can all be overridden from the environment.

## Capture (optional)

```bash
./scripts/mitm.sh start   # wireguard server on udp/51820 + client conf
# phone: WireGuard app -> import /sdcard/Download/eokul-mitm.conf -> activate
./scripts/verify-mitm.sh  # launch app, print decrypted requests
./.venv/bin/python scripts/flows.py --body
```

See `08-mitm.md` for the architecture and troubleshooting.

## What cannot be reproduced without the device setup

| Item | Why |
|---|---|
| `dump/strings_dump.json` | requires installing the *original* MEB-signed app on a rooted emulator and reading the PairIP-populated ghost-class fields from `/proc/<pid>/mem` (`03-strings.md`) |
| Runtime verification | needs a real arm64 device; the x86 emulator stalls on `LicenseActivity` |
| Tunnel activation | one manual tap (Android forbids silent `VpnService` start) |
